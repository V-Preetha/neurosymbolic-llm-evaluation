# NL2Logic + Z3 Bridge Design

## Goal

Replace the monolithic, one-shot raw-FOL bridge in `final_experiment` with a faithful recursive NL2Logic semantic parser that produces a validated FOL AST, an explicit two-pass Z3 compiler, and a separate three-way solver. Preserve the four experimental conditions, frozen sampling manifests, and the 10,000-example ProofWriter `main` training selection.

## Experimental contract

- Condition 1 remains base Qwen3-8B direct classification.
- Condition 2 becomes base Qwen3-8B + recursive NL2Logic + two-pass compiler + Z3.
- Condition 3 remains fine-tuned Qwen3-8B direct classification.
- Condition 4 becomes fine-tuned Qwen3-8B + recursive NL2Logic + two-pass compiler + Z3.
- Conditions 2 and 4 differ only in the model weights used by the semantic parser. They share the AST, compiler, solver, prompts, recursion policy, and evaluation examples.
- Bridge fine-tuning supervises parser-selector and subparser JSON outputs. It never trains or modifies the compiler or solver.
- Existing train, validation, and test manifests remain the only sampling authority. No manifest is regenerated by this change.

## Architecture

### Typed FOL AST

`final_experiment/fol_ast.py` owns AST parsing, normalization, and validation. Supported nodes are predicate, not, and, or, implies, iff, forall, and exists. Validation rejects malformed nodes, empty predicate argument lists, inconsistent predicate arities, invalid variable names, and free variables. A theory contains one or more premises and one hypothesis.

### Recursive NL2Logic semantic parser

`final_experiment/nl2logic_parser.py` ports the structure of `nsce-evaluation/external/nl2logic/pipeline.py` while using the existing local `ModelRunner` interface. For each natural-language sentence it:

1. invokes a selector for atomic, quantified, binary-logical, or unary-logical structure;
2. invokes the selected component parser;
3. recursively parses returned child clauses;
4. constructs and validates a typed AST node;
5. rejects empty, unchanged, cyclic, or over-depth child clauses rather than silently treating them as valid logic.

Atomic parsing includes a relation selector and adjective, intransitive, transitive, and ditransitive subparsers. Theory parsing splits the normalized dataset context into premise sentences and parses the hypothesis independently.

The parser accepts a generation callable so production uses Qwen3-8B and tests use a deterministic scripted generator without loading model weights.

### Complete parser traces

Every recursive parser step emits a condition-specific JSONL event, including failed and partial parses. Events contain:

- dataset, condition, run, example, sentence, step, parent-step, and recursive-path identifiers;
- recursion depth, input clause, and premise/hypothesis role;
- selector raw output, selector decision, and selector validation status;
- chosen subparser and its raw output;
- every child clause and child-step identifier;
- returned AST node as JSON when available;
- validation status and validation errors;
- terminal status and explicit failure reason;
- model latency and token counts accumulated for the step.

Events are appended in deterministic depth-first order to `parser_traces.jsonl` inside each condition run directory. A step event is finalized in a `finally` path, so exceptions cannot erase partial trace state.

### Two-pass compiler

`final_experiment/z3_compiler.py` is independent of parsing and solving.

- Pass 1 traverses the validated AST and creates a declaration table for the object sort, constants, bound variables, predicates, and predicate arities. Arity conflicts and scope violations are compiler failures.
- Pass 2 uses only that declaration table to generate Z3 expressions. It does not execute generated Python or accept raw FOL strings.

The compiler returns a compiled theory containing premise expressions, the hypothesis expression, and auditable declaration metadata.

### Solver and semantic agreement

`final_experiment/z3_solver.py` owns solver construction and status mapping. It first verifies premise consistency, then checks entailment of the hypothesis and its negation to return `True`, `False`, or `Unknown`. Parser, compiler, timeout, unknown, inconsistency, and unexpected solver failures remain system failures rather than logical `Unknown`.

Where a gold AST is available, semantic agreement compiles predicted and gold expressions and asks Z3 whether their XOR is satisfiable. It reports `equivalent`, `different`, `solver_unknown`, or `not_available`; it also retains normalized AST exact-match metrics. Quantified cases may legitimately produce `solver_unknown`.

### Parser fine-tuning records

`final_experiment/nl2logic_training.py` converts each gold theory into component-level training records. Root records pair the original sentence with its gold node. Nested records use deterministic canonical natural-language renderings of child AST nodes. Records cover the parser selector, relation selector, and selected atomic/quantified/logical subparser. Each record stores a prompt and JSON target; training loss masks the prompt and supervises only the component response.

The original dataset row manifest still controls selection: expansion into component records happens only after the selected rows have been materialized.

## Evaluation and metrics

Bridge evaluation parses every premise and hypothesis through the recursive parser, validates the completed theory, compiles it, and solves it. `predictions.jsonl` records:

- parser completion and AST validity;
- compile success;
- executable rate, defined as a completed parse plus successful compile plus completed solver call;
- normalized AST and semantic/gold-FOL agreement where available;
- final solver prediction and correctness;
- accumulated parser, compiler, and solver timing/tokens.

`analysis.py` aggregates AST validity, compile success, executable rate, semantic agreement categories, and final solver accuracy. Direct conditions remain unchanged.

## Compatibility and migration

`final_experiment/bridge.py` remains as a small compatibility facade re-exporting legacy names used by existing smoke tests and callers. It delegates validation, compilation, and solving to the new modules. Existing frozen manifests and checkpoint directory naming are not changed.

## Verification boundary

Verification is limited to unit tests, deterministic mocked recursive-parser tests, and the no-model smoke command. No Qwen weights are loaded, no adapter training is started, and neither `main` nor `full` evaluation is run.
